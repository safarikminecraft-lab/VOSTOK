# VOSTOK — собственный сервер + подключённый клиент

Это самостоятельный backend для VOSTOK. Клиент (`public/index.html`) уже подключается к API этого сервера: регистрация/вход, поиск зарегистрированных аккаунтов, личные диалоги и серверные сообщения.

## Функции
- Регистрация: nickname, уникальный username, пароль (bcrypt).
- Вход с другого устройства: JWT-токен, срок 30 дней.
- SQLite база: пользователи, диалоги, участники, история сообщений.
- Поиск по nickname/UserName — только реальные записи БД; текущий аккаунт не показывается.
- Личные чаты создаются/получаются повторно, не дублируются.
- Обмен сообщениями через REST + Socket.IO, без перезагрузки страницы.
- Редактирование/удаление своих серверных сообщений.
- Изменение nickname/avatar сохраняется в базе.
- Socket.IO авторизуется токеном и проверяет членство в комнате.
- Health endpoint: `/api/health`.

## Локальный запуск (компьютер)
Нужен Node.js 20 или новее.

1. Распаковать архив.
2. В папке проекта выполнить `npm install`.
3. Скопировать `.env.example` в `.env`, придумать JWT_SECRET длиной 32+ символа.
4. Выполнить `npm start`.
5. Открыть `http://localhost:3000`.

Не открывайте HTML через `file://`: приложение должно быть открыто с адреса запущенного сервера.

## Публикация в интернете с телефона (Render Blueprint)
1. Загрузить папку проекта в GitHub-репозиторий (можно через мобильный браузер GitHub: создать репозиторий и загрузить файлы; архив ZIP сначала распаковать).
2. В Render выбрать New → Blueprint и подключить GitHub-репозиторий с `render.yaml`.
3. Blueprint создаёт Node web-service, автоматически генерирует `JWT_SECRET`, подключает постоянный диск `/var/data` для SQLite и использует `/api/health` как проверку.
4. После deploy открыть выданный Render URL. Это и есть адрес VOSTOK. Не открывать исходный HTML напрямую.
5. Создать два разных аккаунта с разных устройств/браузеров, искать username второго, начать чат, отправить сообщение и проверить получение.

SQLite файл хранится на подключённом диске `/var/data/vostok.sqlite`. Без persistent disk база может исчезнуть при пересоздании сервиса. Render Blueprint может потребовать тариф, поддерживающий persistent disk.

## Переменные среды
- `PORT` — задаёт хостинг автоматически (локально 3000).
- `JWT_SECRET` — обязательный в production, минимум 32 символа.
- `VOSTOK_DB_PATH` — путь к SQLite (по умолчанию `./vostok.sqlite`).
- `PUBLIC_ORIGIN` — необязательные comma-separated origins, если API/socket подключаются с другого домена. При раздаче клиента тем же сервером обычно оставьте пустым.

## API
- `POST /api/auth/register` `{username,nickname,password,avatar?}`
- `POST /api/auth/login` `{username,password}`
- `GET /api/me` (Bearer token)
- `PATCH /api/me` (Bearer token; nickname/about/avatar)
- `GET /api/users/search?q=...` (Bearer token)
- `POST /api/chats/:userId` — создать или вернуть DM
- `GET /api/chats` — список DM
- `GET /api/chats/:id/messages` — история
- `POST /api/chats/:id/messages` `{body}`
- `PATCH /api/messages/:id` `{body}` — редактирование своего сообщения
- `DELETE /api/messages/:id` — удаление своего сообщения
- Socket.IO: `chat:join`, `message:new`, `message:edited`, `message:deleted`, `typing`, `presence:update`, `call:signal`.

## Ограничения текущей версии
- Сообщения — текст; прикреплённые файлы/голосовые в текущем HTML пока остаются локальной демонстрационной функцией и не загружаются на сервер.
- Звонки — только сигналинг заготовлен, полноценная WebRTC реализация и TURN-сервер не включены.
- Система уведомлений браузера работает отдельно; push-уведомления при закрытом браузере не реализованы.
- Перед публичным запуском нужны дополнительные меры (более строгие лимиты, CAPTCHA/проверка email, восстановление пароля, бэкапы, moderation/reporting).
